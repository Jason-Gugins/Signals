## ADDENDUM — taxonomy 422 root cause (2026-10-13), and it's bigger than typing

Penny-bisect + 422 body capture (tmp/typing422_probe.py): every variant —
1×54, 1×27, 1×13, 1×7, 1×3 criteria, 2×54, 5×54, even a minimal 1-noul
request — returns the SAME rejection:

    loc: ["body","questions","type_0","choice","criteria"]
    msg: "Input should be a valid dictionary"
    input: ["annual_report_10k: …", "award: …", …]

**TypeSafe requires `criteria` to be a DICT (`{label: description}`); the
typing battery sends a LIST.** The planned hierarchical reshape is dead —
no criteria count or payload size is involved.

**And the blast radius is four gates, not one.** gates.py ships list-shaped
criteria in THREE places: taxonomy typing (54 entries), posture_audit
(`within_posture/outside_posture`, gates.py:685) and G3 routing
(`deep/quick`, gates.py:769) — while every gate that WORKS (G4's Choice
gates.py:1000, event-dates 2088/2102) sends dicts. Reconciliation with the
run history is exact: the "4–6 Jev errors on every run" that this project
has recorded since the decide layer shipped ARE the routing + posture_audit
422s (Jev is invoked on routing only within the tie band — hence "3–4 per
run"); the typing 422s are the same bug at scale; and the breaker cascades
that fail-closed G4 (helcim: 105 rows) were tripped by these chronic 4xxs.
The jev.py docstring documents `"criteria": [...]` as canonical — the code
and TypeSafe's schema have disagreed since birth.

**Fix shape (single point, all gates):** normalize at the request boundary
in `src/decide/jev.py` — list criteria → `{label: ""}` dict before the
POST. One change heals taxonomy typing (first-ever success), routing, and
posture_audit simultaneously; dict-criteria gates pass through untouched.
Plus: `Decision.cause` gains the 422 response body snippet (the diagnosis
depended on reading bodies the old cause field discarded).
